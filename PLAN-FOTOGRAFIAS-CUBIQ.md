# CUBIQ — Fase 4: Planificación híbrida de obtención de fotografías

**Estado:** planificación (sin ejecución). **No se descargaron imágenes, no se compraron productos, no se modificó código, catálogo, diseño ni funcionalidades.**  
**Estrategia híbrida elegida:** (1) **fotografías propias** de productos físicos; (2) **fotografías de fabricantes o distribuidores** solo cuando exista **autorización expresa** o **licencia compatible con uso comercial** verificable.  
**Documentos consultados:** `CATALOGO-CLASIFICACION.md`, `PRODUCTOS-REALES-CANDIDATOS.md`, `SELECCION-REAL-CUBIQ.md`, `IMAGE-AUDIT.md`.

## Reglas obligatorias (aplican a todo el plan)
- **No basta con que una foto esté publicada** en una web comercial. Para reutilizar una fotografía de tercero se requiere **autorización o licencia compatible verificable** (documento, correo con términos claros, contrato o licencia explícita) que cubra el uso previsto en CUBIQ (web/e-commerce, alcance, territorio y duración según corresponda).
- **Correspondencia 1:1:** cada imagen debe representar **exactamente** la marca, modelo y **variante** seleccionada (acabado/color/edición/mecánica si aplica). Prohibido asignar por semejanza.
- **Sin invención:** no se inventan contactos, permisos ni características. Los datos de contacto/canales solo se incluyen si están publicados en fuentes oficiales ya documentadas.
- **Formato de evidencia mínima (antes de integrar):** `id/slug CUBIQ | marca + modelo + variante/SKU | fuente(s) de specs | origen de foto (propia / fabricante / distribuidor) | autorización/licencia (texto/archivo verificable) | archivo local + resolución | confirmación humana 1:1`.
- **No usar:** SVG/dibujos/ilustraciones/imágenes generadas como “foto real”; JPG heredados descartados para asignación sin confirmación humana de contenido/correspondencia/licencia (`IMAGE-AUDIT.md`).

## 4) Guía para tomar fotografías propias con celular (CUBIQ)

Objetivo: obtener fotos **reales**, nítidas, consistentes y con **correspondencia 1:1** a la variante exacta.

### Preparación
- Confirmar **variante exacta** (modelo, acabado, color, edición). Incluir una nota interna/foto de empaque o etiqueta si ayuda a evidenciar la variante (no necesariamente para publicar).
- Limpiar el producto (huellas/polvo). Revisar que no haya daños que confundan la representación.

### Fondo
- Usar fondo **liso y neutro** (blanco, gris claro o color uniforme) sin texturas distractoras.
- Evitar fondos con marcas, patrones o reflejos complejos. Mantener consistencia entre productos.

### Iluminación
- Preferir **luz difusa** (cerca de ventana con luz indirecta, o difusor). Evitar flash directo duro.
- Evitar sombras marcadas y reflejos excesivos (especialmente en acabados **UV/glossy**). Si hay reflejos, ajustar ángulo/luz.
- Balance de blancos neutro; no aplicar filtros que alteren el color real del producto.

### Ángulos y tomas recomendadas (mínimo útil)
1. **Frontal/3 cuartos** (principal, producto completo y centrado).  
2. **Ángulo alterno** (otro 3/4) para mostrar volumen.  
3. **Detalle relevante** (logo/textura/acabado) solo si no confunde y corresponde a la variante.  
4. Opcional: vista superior o lateral si aporta claridad (sin recortar partes críticas).

### Encuadre y composición
- Producto **completo** dentro del cuadro, centrado, con margen uniforme.
- Cámara a la altura adecuada (evitar deformaciones exageradas). Mantener horizonte/nivel.
- No incluir manos, objetos ajenos ni texto superpuesto que no sea parte del producto.

### Resolución y calidad técnica
- Disparar en la **máxima resolución** disponible del celular; usar lente principal (evitar zoom digital si reduce calidad).
- Enfocar el producto (tocar pantalla). Evitar fotos movidas; apoyar el celular o usar temporizador si es posible.
- Formato de salida preferible: **JPEG de alta calidad** (o equivalente). Evitar compresión excesiva al exportar/compartir.
- **Objetivo CUBIQ (alineado a requisitos del proyecto):** ideal **≥ 1000 × 1000 px** para la imagen principal; mayor resolución es aceptable si se mantiene nitidez.

### Control 1:1
- Verificar antes de dar por válida: que la foto sea del **mismo modelo y variante** que se integrará (acabado UV vs frosted, cantidad de imanes/edición si es visible o documentada, color). Registrar evidencia (factura, empaque, SKU) internamente.

## 5) Requisitos uniformes para las imágenes de CUBIQ

| Requisito | Estándar CUBIQ |
|---|---|
| Tipo | **Fotografía real** del producto. No SVG, no dibujo, no ilustración, no render presentado como foto, no imagen generada por IA. |
| Correspondencia | **1:1** con marca, modelo y **variante** exacta. Sin asignación por semejanza ni reutilización entre productos. |
| Derechos | Imagen **propia** o de tercero con **autorización/licencia compatible verificable** (uso comercial/web según aplique). Publicación en web de terceros **no** implica permiso. |
| Calidad | Nítida, bien expuesta, sin pixelado evidente, sin ampliación artificial engañosa. |
| Resolución | **Ideal ≥ 1000 × 1000 px** (principal). Mantener proporción y legibilidad del producto. |
| Composición | Producto centrado, completo, fondo neutro uniforme, iluminación consistente. |
| Formato/almacenamiento | Archivo local en repositorio (no enlaces temporales). Ruta prevista por convención: `public/images/products/<categoria>/` con nombre descriptivo (kebab-case, incluye marca/modelo/variante cuando aplique). |
| Naming sugerido (al integrar) | `marca-modelo-variante-vista.jpg` (ej. `gan-251-m-pro-front.jpg`). Evitar nombres genéricos. |
| Trazabilidad | Registrar fuente, autorización/licencia, resolución, fecha y confirmación 1:1 en `IMAGE-AUDIT.md` (y evidencia asociada) antes/después de integración. |
| Proceso de integración | Solo tras autorización + verificación; sin cambios de diseño/funcionalidad; validar `node scripts/validate-catalog.mjs` y `cmd /c "npm run build"`. |
